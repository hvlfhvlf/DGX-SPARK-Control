# 0.3.3 — 2026-11-06

Stable Ubuntu 24.04 ARM64 release incorporating the tested 0.3.3~rc1–rc6 runtime. Version, documentation and privacy exclusions are updated; runtime behavior matches rc6.

## Changes / 변경 사항

- Harness: authenticated, on-demand current app launch URL without persisting its startup token in the registry.
- Service Details: optional official application version/check/update and private backup/recovery for supported, locally bound Harness, Hermes and ComfyUI installations. Running/unknown app states block updates; no automatic app stopping or startup.
- Boot autostart: selected registered user-service profile ON/OFF, revision/conflict/maintenance checks, actual state and linger guidance.
- Reliability: shared bounded collection, incremental visible history, lazy activity, three browser requests at a time, eight bounded server workers, delayed/disconnected distinction and automatic retry of eligible GETs only.
- UI: hidden service/update dialogs stop polling, stale errors cannot reopen dismissed dialogs, initial values show Connecting/unavailable rather than false failures or zero CPU cores.

상세창에 앱 버전·공식 업데이트·백업·복구와 부팅 자동 시작을 제공합니다. 연결 지연과 끊김을 구분하고 보이지 않는 이력·상세창의 불필요한 요청을 줄였습니다. 기존 개인 설정·로그인·모델 파일을 보존합니다.

## Validation / 검증 범위

The rc6 runtime passed **94 Linux Python tests and 59 Node tests**. Browser checks covered all five tabs, eight metric dialogs, service Details, unsaved-edit cancellation, search/sort, two-stage power preparation without execution, English/Korean and black/white modes, and 320/390 px overflow/two-column checks. Earlier candidate tests covered autostart ON/OFF restoration, update guard/failure recovery and private backup byte comparison; production upstream applications were not upgraded merely for validation.

The preceding connection soak completed approximately **33 minutes**, ending at the owner's request: 6,475/6,475 HTTP 200 requests across five logical clients and 1,496/1,496 HTTP 200 in a real PC browser; no observed disconnect indicator or browser JavaScript error. These were not five physical devices or a full one-hour run. The subsequent rc6 installed audit passed 54/54 concurrent reads; dashboard/tray were about 149 MiB current / 172 MiB inherited peak with a 480 MiB hard limit and no recorded OOM. These measurements are not an inference performance benchmark.

정식 패키지의 최종 테스트·공개 다운로드 체크섬·Spark 설치 및 보존 검증 결과와 소스 커밋은 [GitHub Release](https://github.com/hvlfhvlf/DGX-SPARK-Control/releases/tag/v0.3.3)에 기록합니다. 이전 후보판 문서의 비공개 상태는 당시 기록입니다.

## Installation and recovery / 설치·복구

Use `dgx-spark-control_0.3.3_arm64.deb` and verify `SHA256SUMS` before `sudo apt install ./dgx-spark-control_0.3.3_arm64.deb`. Fresh installs run `dgx-spark-control setup` as the normal user; existing activated package installs retain settings and remembered sessions. [한국어 간편 설치](../QUICKSTART.ko.md) · [English quickstart](../QUICKSTART.en.md).

Dashboard rollback uses a previous trusted `.deb` through apt with an explicit downgrade; do not run archive rollback scripts on a package installation. App update recovery is a separate mechanism: [service updates](../SERVICE-UPDATES.md).

## Limits / 한계

- App updates require an existing compatible install and an explicit private local binding; discovery/registration alone does not authorize updates. No automatic engine/model installation, driver update or ComfyUI custom-node update.
- Temporary updater: up to 2 GiB outside the dashboard/tray's 480 MiB cap; exits after work. Checking creates no backup. Applying requires free disk space; one successful managed backup per service is retained, while unresolved recovery material requires local review.
- Basic validation/restore tests do not guarantee every app plugin, provider, workflow or future official release. Apps remain stopped after updating for the owner's verification.
- Physical iPhone Safari, unstable Wi-Fi, actual host power execution and production app upgrades were not part of the final regression pass.
- No production credentials, personal routes/registries, model files, raw logs or conversations are shipped. Generic synthetic test credentials are intentional. Privacy scanning cannot prove absence of every possible secret.
