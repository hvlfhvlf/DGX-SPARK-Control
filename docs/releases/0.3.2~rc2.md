# 0.3.2~rc2 — local candidate

Not published. Based on public 0.3.1 (`5dd37e1c718377a72374f262a0974c60796bfcab`), including local rc1.

## Changes

Current health, connection verification and the last control request are distinguished. Reviewed confirmation is bound to the registry revision/profile. Detail controls refresh on every page, and fail closed when disconnected or changed. Failed Stop retries Stop. Successful responses from an earlier session are rejected. Readiness reuse requires the same systemd invocation and registry revision. Copy explains registration versus installation, control permission versus connectivity, shared versus browser preferences and clearing all finished activity.

## Verification

- Linux Python: 59 tests passed, including restart/reconfiguration readiness-cache regression (failed before the fix).
- JavaScript: 33 tests passed; syntax checked for every web script. Covers offline/unknown states, recovered API versus historical failure, action binding, failed-stop retry, cross-page polling, late session responses and initial/sign-in connection states.
- Real disposable user services: start, stop, restart, switch while stopped, failed start and recovery; duplicate requests, running profile switch, unsigned requests and untrusted Origin rejected. Production model services were not controlled by these tests.
- Package/live/browser checks are recorded in the private project audit report and Notion. No passwords, private service registry or operational logs are included here.

## Limits

This is not proof of every possible browser or engine failure. No physical iPhone/Safari session, destructive power execution, real model OOM injection or long-duration inference benchmark is included. Prior persistent-login and power validation unit tests remain in the full suite.
