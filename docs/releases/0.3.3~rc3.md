# 0.3.3~rc3 — private candidate, 2026-11-05

Adds opt-in official application updates in service Details. Installed versions are separate from model labels. Checking is explicit; a reviewed candidate changes the button to Update. Running applications are blocked by both the API and local user-unit conditions. No automatic stopping or restarting occurs.

Harness uses versioned official npm releases. Hermes invokes its official updater with restart disabled. ComfyUI pins the reviewed official commit, updates requirements with existing Torch versions constrained, and leaves custom nodes and model/media directories untouched. ComfyUI custom-node compatibility and real generation remain separate validation.

Code, mutable virtualenv and app state are copied before mutation (Harness retains old release directories). Recovery quarantines the failed tree and restores the prior copy. Crash/timeout recovery runs from ExecStopPost; after a host power loss, a retained guard requires local recovery. Recovery failure keeps starts blocked. Backups are private and never bundled.

Updater resources are separate from the dashboard: 2 GiB RAM, no swap, 150% CPU, 128 tasks, one-hour deadline. Dashboard/tray retain their combined 480 MiB cap. Basic CLI/import/dependency validation is not proof of every plugin, provider or workflow. Services remain stopped for the owner's app-level verification.

Validation (2026-11-05): 81 Python tests on Spark/Linux and 42 JavaScript tests passed; JavaScript syntax, shell syntax and diff whitespace checks passed. A disposable real user service verified the running-service guard, transient update worker rollback and ExecStopPost crash recovery. An uncertain worker-launch result retains the guard instead of assuming nothing started. These tests did not inject failures into production applications.

Private snapshots of the stopped installed Hermes and ComfyUI trees were compared file-by-file against their originals: Hermes 195,544 files / 4,714,492,773 bytes; ComfyUI 78,319 files / 8,959,322,168 bytes; all SHA-256 comparisons matched. Excluded model/media/custom-node directories were not copied or modified. Backups remain local and private.

Installed dashboard upgraded privately from rc2 to rc3 and reinstalled successfully. Authentication, sessions, settings and registry hashes were preserved; existing application process identities/states were preserved. Measured dashboard slice was about 68 MiB current / 76 MiB peak with the existing 480 MiB cap. Real browser Details were checked at desktop, 390 px and 320 px without horizontal overflow; this is not physical iPhone/Safari verification.

No upstream production application was upgraded during verification. Harness was already on the checked npm latest release and was left running. Hermes has a pre-existing nonzero doctor result; a completed update with a nonzero doctor on both sides is marked for review, not declared fully healthy. New provider/plugin/workflow compatibility still needs application-level verification. Public GitHub remains v0.3.2; this candidate has not been committed, pushed, tagged or published.

Retention: update checks create no backups. After a successful validated update, keep one managed rollback snapshot per service. Older snapshots are pruned only after validation. Failed/review-required updates retain evidence and block repeated attempts until local review. Partial pre-mutation backups are removed. Harness retains current/previous updater-owned releases; manual installations are untouched. Temporary old/new/restore copies still require extra disk space. Verification snapshots join this policy.

Model Bay actions use an optional full-width Open App row ABOVE a fixed bottom row: Start/Stop on the left, Details on the right. Services without an app URL still keep these two bottom buttons aligned.
