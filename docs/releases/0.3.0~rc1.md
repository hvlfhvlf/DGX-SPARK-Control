# 0.3.0~rc1 — local release candidate, 2026-11-02

Not published to GitHub. Metrics-detail redesign and service/profile controls. Config/auth schema stays 1; separate private service registry schema 1. No engine, model, driver or Tailscale route update is bundled.

## Verified on the existing Spark

- 28 Linux unit/API tests and 7 telemetry-data Node tests passed; all web JavaScript and installation/update/rollback shell syntax checked.
- Disposable real systemd user units: start, stop, changed-PID restart, failed start, duplicate-operation rejection, stopped-profile selection/start, unsigned-request rejection and cross-origin rejection passed. Tests did not stop the user's ComfyUI, Qwen or Hermes to generate evidence.
- A brief process transition exposed a false-success race during testing. Start completion now requires two consecutive running observations; the real failed-start test then passed.
- Existing ComfyUI API and running/pending counts were read successfully without forwarding workflow bodies. Qwen is registered to its existing service with process-only observation; Hermes likewise reports gateway process state. Their end-to-end inference/provider behavior was not retested.
- Actual candidate package update → prior private package rollback → candidate reinstall passed authenticated health checks. The service registry survived rollback; existing name/config/password/session/token file hashes were preserved. Fifty other running user-service PID/start records stayed unchanged.
- Live 1440/390/320 px: all eight metric details stayed within the dialog width; overview retained eight cards and two mobile columns. All three service cards/details passed 24 Korean/English desktop/mobile geometry checks; discovery and keyboard-focused expanded notes were checked. Language changes rebuild the service interface after the selected language updates. Expanded notes/focus survived more than a minute of refreshes.
- Observed dashboard+tray memory: 60,792,832 bytes (about 58.0 MiB); observed slice peak 70,336,512 bytes (67.1 MiB, cumulative observation). Hard cap 503,316,480 bytes, swap cap 0. memory.events high/max/OOM/OOM-kill counters were 0. This is not an inference overhead benchmark.
- An isolated instance of the same server code served eight metric reads from one cached sample; its collection count did not increase during 12 seconds without metric requests. Production browsers remained available throughout.
- Candidate archive and deb contents scanned for known local identifiers, private addresses/paths, actual local auth material and common credential patterns; no matches. No private registry, logs, cache files or account-name owner metadata were packaged. Archive entries use numeric root IDs and blank names; deb entries use root ownership.
- Source review found only same-origin `/api/` fetches in the active runtime/control/detail modules; engine probes use fixed local paths on validated loopback origins. No external analytics/reporting service was added. This is a scoped review, not a claim that every possible vulnerability has been excluded.

Final artifacts and SHA256SUMS are prepared locally. Exact package hashes belong in SHA256SUMS and the Notion delivery record, not inside the artifact that they hash. No GitHub push, tag or Release is part of this delivery. See docs/development/METRIC-DETAILS-LOCAL-VALIDATION.md for preceding detail-only builds and docs/MODELS.md for the current service contract.

Limitations: process/API status is not inference quality/performance proof. TensorFold-specific metrics, Hermes conversation/provider checks, automatic hot switch/rollback, engine load/unload, raw logs and other platforms are not implemented. No physical iPhone/Safari certification or fresh-OS installation is claimed.
