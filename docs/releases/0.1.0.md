Status: **Spark runtime and release-candidate validation passed**. Published-asset download verification is recorded in the GitHub Release notes after publication.

Requirements: Spark-hosted, simple installer, explicit version updates, 512 MB maximum dashboard RAM, server-persisted DGX_SPARK name, public GitHub source/release, corresponding Notion record, LLM continuation guides.

## Performed

- DGX Spark / NVIDIA GB10, ARM64, Ubuntu with Python 3.12.3, user systemd and cgroup v2.
- Five Linux API tests pass: authentication/Origin, rename persistence and invalid names, control allowlist, path traversal, cached collection and unavailable initial rates.
- JavaScript syntax and installer/update/rollback Bash syntax pass.
- Real install, restart, reinstall, previous-code rollback and restored upgrade pass. Shared name and private token survive all steps; default `DGX_SPARK` restored after testing.
- An isolated disposable user service was started and stopped through the real API. Candidate discovery found a fixture without modifying it. No existing inference service was stopped for testing.
- Desktop browser: all eight metric dialogs open and close; settings rename survives reload. Chrome at 320px and 390px keeps two columns and fixed 190px cards without card overflow.
- Tailscale Serve HTTPS verified from Spark and a second Windows device. Private APIs still require the dashboard token. Device-specific addresses are kept outside the public repository.

Reproduce with `python3 scripts/measure.py` on an installed Spark. These are a short synthetic test, not a long-term or inference-performance benchmark. The browser, Tailscale and model engines are separate from this service budget.

## Not performed / limits

- No controlled before/after LLM workload benchmark or multi-day memory soak.
- Chrome was tested; Safari, Firefox, iOS and other Linux distributions have not been run. Standard browser APIs, local fonts and reduced-motion fallbacks are used; this is not a claim of universal tested compatibility.
- Inference engine readiness, tok/s, global job queues, model downloads/deletions and automatic engine adapters are future work. The registry controls configured user-systemd services only.
- Unsupported sensors display `—`; there is no inferred whole-system wattage or inferred memory clock.
- History is bounded in memory and resets with the server. No dashboard requests means no new telemetry samples.

Release procedure and version-by-version GitHub/Notion synchronization: `docs/UPDATES.md` and `AGENTS.md`.

No claim of measured inference overhead until a controlled before/after workload benchmark has run. A service memory limit alone is not a measured resident usage result. No existing inference workload may be interrupted just for validation.
