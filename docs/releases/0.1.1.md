# 0.1.1 validation record — 2026-10-08

This release adds detected hardware capacity, installation passwords, persistent device login, local desktop recovery and SSD accounting detail to 0.1.0. Published-asset download/update results are recorded in the GitHub Release notes after publication.

## Performed

- 11 Linux tests pass: existing auth/Origin/control/cache/path tests, 64/128/256 GiB firmware fixtures, missing-firmware fallback, password hashing/login/logout, persistent session restart/password-reset behavior, session bounds and reserved disk-space accounting.
- Actual Spark firmware: installed 128 GiB, OS MemTotal about 121.7 GiB, GPU NVIDIA GB10, aarch64 and 20 logical CPUs. The UI reads these values from the authenticated hardware API. 64 GiB was tested with fixtures, not a second physical machine.
- A user-selected password was entered interactively without echo, saved as a hash and verified through the real HTTPS browser login. No actual password appears in source, release assets or this record.
- Actual server restart followed by browser reload and a newly opened tab retained login. Device sessions have no fixed expiry by owner request. Password reset invalidates previous sessions; local recovery does not need the old password.
- GNOME StatusNotifierWatcher registered the tray; its D-Bus menu exposes dashboard open, name change, password reset, start/restart and status. The tray service is active. Direct physical-desktop clicking/visual inspection was not performed.
- SSD API compared with `df -B1`: identical total capacity; used/available differed by one 4 KiB block between sequential reads while the machine was working. The displayed root filesystem also backs the home directory on the validation device. Detail UI distinguishes actual used space, user-available space, reserved-free space and df percentage.
- Combined server + tray cgroup observed 51,179,520 bytes (48.8 MiB), peak 52,764,672 bytes (50.3 MiB), enforced memory.max 503,316,480 bytes (480 MiB). The optional tray does not poll telemetry.

## Compatibility and boundaries

Config schema remains 1. `password.json`, `sessions.json` and `hardware.json` are outside release code; updates preserve credentials and sessions. The installer re-probes hardware once; it never guesses 64/128 GB from OS usable RAM. Missing dmidecode permission falls back to explicitly labeled MemTotal.

Headless server still uses Python standard library only. Optional desktop tray uses GTK3 / Python GI / Ayatana AppIndicator. On the validation Spark only the small missing GI AppIndicator binding was installed from Ubuntu; model packages and running model services were not changed.

32 remembered device sessions are retained; a 33rd login removes the oldest issued session. Browser localStorage stores only its random session secret; server stores its SHA256 hash. Logout, password reset or browser data deletion require a new login. No timed reauthentication is imposed.

0.1.0 rollback uses its older token-only UI and has no tray/password login. For persistent device login, remain on 0.1.1 or newer compatible releases. Existing model services are not controlled by updates.

Not tested: physical 64 GiB hardware, Safari/Firefox/iOS, multi-day memory soak, and before/after inference-performance benchmarks. [0.1.0 resource benchmark](0.1.0.md) is separate from this short post-login combined-memory observation.

Version documentation and Notion synchronization are required by `AGENTS.md` and `docs/UPDATES.md`.
