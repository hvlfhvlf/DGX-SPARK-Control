# DGX-SPARK-Control 사용자 가이드 — 한국어

**0.3.1** · [English](GUIDE.en.md) · [간편 설치](QUICKSTART.ko.md)

## 설치·접속

[간편 설치 가이드](QUICKSTART.ko.md)에 따라 `.deb`를 설치하고 앱 목록의 **DGX-SPARK-Control 초기 설정**을 엽니다. 한국어·영어를 선택하고 이름·비밀번호를 저장하면 서버가 시작됩니다. 기존 비밀번호를 유지하려면 두 칸을 비워두세요.

Spark 자체에서는 `http://127.0.0.1:8767`, 다른 기기에서는 Tailscale HTTPS 주소로 접속합니다. 트레이의 **접속 주소 복사**는 연결된 HTTPS 주소를 우선 사용합니다. Tailscale 연결이 없으면 로컬 주소를 복사하고 안내합니다.

## 로그인과 복구

같은 브라우저·같은 주소에서는 기간 제한 없이 로그인합니다. 재시작·업데이트 후에도 유지됩니다. 로그아웃, 비밀번호 재설정, 브라우저 데이터 삭제 시 해제됩니다. 다른 브라우저·주소·시크릿 창에서는 새 로그인이 필요할 수 있습니다. 최대 32개 세션이며, 33번째 발급 시 가장 오래된 세션이 제거됩니다.

비밀번호를 잊으면 Spark 로컬 트레이의 **비밀번호 재설정**을 사용합니다. 기존 비밀번호는 필요하지 않습니다. 패키지 설치판에서 터미널로 복구하려면:

```bash
python3 /usr/lib/dgx-spark-control/scripts/set-password.py
systemctl --user restart dgx-spark-control
```

비밀번호 원문은 저장하지 않습니다. 비밀번호 해시·토큰·세션 파일을 공유하거나 GitHub에 올리지 마세요.

## 실제 측정값

| 카드 | 내용 |
|---|---|
| GPU | 사용률과 지원되는 SM 클럭 |
| CPU | 전체·코어별 사용률, 읽을 수 있는 클럭 |
| 통합 메모리 | OS 사용량·총량과 메모리 사용률 |
| SSD | `/` 파일시스템 사용량·총량·사용자 가용·예약 여유 공간 |
| GPU 온도 | 드라이버가 제공하는 온도 |
| GPU 전력 | GPU 센서 값. 전체 시스템 콘센트 전력과 다름 |
| 네트워크 | 물리 인터페이스 수신·송신 MB/s. 인터넷 트래픽만 분리한 값이 아님 |
| 디스크 I/O | 물리 디스크 읽기·쓰기 MB/s |

카드를 눌러 실제 이력과 상세값을 봅니다. 미지원·초기 준비 중 값은 `—`입니다. 설치 RAM은 읽을 수 있는 펌웨어 용량을 사용하고, 없으면 OS 총량임을 표시합니다. 64/128 GB로 임의 추정하지 않습니다. SSD 카드의 사용 비율과 `df` 퍼센트는 예약 공간 때문에 다를 수 있습니다.

## 설정과 트레이

Spark 표시 이름은 모든 기기에 반영됩니다. OS 호스트명·Tailscale 주소는 변경하지 않습니다. 웹 언어·개인화는 브라우저별 설정입니다. 설치 마법사 언어는 로컬 설정에 저장됩니다.

트레이에는 대시보드 열기, 주소 복사, 초기 설정, 업데이트 확인, 이름 변경, 비밀번호 재설정, 서버 시작·재시작, 상태, 닫기가 있습니다. 업데이트 확인은 GitHub 페이지를 열며 자동 설치하지 않습니다. 서버 재시작은 모델을 재시작하지 않습니다. 트레이를 닫아도 서버는 유지됩니다.

## 모델 관리

이미 설치된 사용자 systemd 서비스를 개인 `services.json` 레지스트리에 등록하고 제어 권한을 설정해야 제어할 수 있습니다. 기존 `config.json.models`는 첫 실행에 한 번 옮깁니다. 모델 후보 검색은 지정 경로에서 파일 후보를 찾는 기능입니다. 모델 다운로드·삭제·자동 등록·자동 교체는 수행하지 않습니다. 서비스 `active`와 실제 추론 준비 완료는 다릅니다.

[모델 연동 가이드](MODELS.md)를 읽고 설정을 백업한 뒤 필요한 모델만 추가하세요. 대시보드는 지원 엔진의 추론 tok/s와 엔진별 요청 수를 표시합니다. TTFT·전역 큐는 아직 제공하지 않습니다.

## 업데이트·자원·문제 해결

`.deb` 설치판은 새 `.deb`를 설치합니다. 패키지와 예전 스크립트 방식은 혼용하지 마세요. [업데이트·복구·이전](UPDATES.md).

```bash
systemctl --user status dgx-spark-control
journalctl --user -u dgx-spark-control -n 50
tailscale serve status
systemctl --user show dgx-spark-control.slice -p MemoryCurrent -p MemoryPeak -p MemoryMax
```

서버+트레이 합산 상한은 480 MiB이며 swap은 0입니다. 브라우저·모델·설정 마법사·Tailscale은 별도입니다. 접속 요청이 없으면 지표를 수집하지 않습니다. 장시간 추론에 대한 영향은 별도 벤치마크가 필요합니다.

다른 LLM이 개발을 이어가면 [AGENTS.md](../AGENTS.md) → [구조](ARCHITECTURE.md) → [모델](MODELS.md) → [업데이트](UPDATES.md)를 읽게 하세요. 비밀 정보는 공개 자료에 포함하지 않습니다. [이번 버전 검증 기록](releases/0.3.1.md).

## 한글 웹폰트 / iPhone

한글 웹 UI는 SUIT 2.0.5를 사용합니다. Regular(400)·SemiBold(600)·Bold(700) WOFF2 파일을 Spark에서 직접 제공하므로 iPhone에 폰트를 따로 설치하거나 외부 폰트 CDN에 접속할 필요가 없습니다. 큰 수치·영문 디스플레이에는 Rajdhani, 영어 UI에는 Chakra Petch를 유지합니다. 폰트 로딩 중이거나 로딩에 실패하면 시스템 한글 폰트로 표시합니다.

Safari는 WOFF2 웹폰트를 지원합니다. 다만 Windows와 iPhone의 글자 렌더링은 미세하게 다를 수 있습니다. [WebKit 폰트 지원 설명](https://webkit.org/blog/6643/improved-font-loading/). 앱 업데이트 후 이전 글꼴이 남으면 페이지를 새로고침하세요. 네이티브 GTK 설정창·트레이의 폰트는 이번 변경 대상에 포함되지 않습니다.

## 지표 상세창

개요의 8개 카드를 클릭하면 각 지표의 상세창이 열립니다. 상단 핵심값, 1분·5분·1시간 추이, 항목별 세부 정보 순서이며 폰에서도 핵심값은 2열입니다. SSD 용량 창은 시간 그래프 없이 사용·가용·사용률·전체 용량, 구성 바, 마운트 위치를 보여주며 **용량 상세 · 계산 기준**을 펼쳐 예약 공간과 df 계산을 확인합니다. 메모리는 사용·가용 공간, CPU는 코어별 부하, 온도는 실제 보고된 센서, 네트워크·디스크 I/O는 두 방향의 속도를 보여줍니다. SSD 용량은 루트 파일시스템 기준이고 전력은 GPU 기준입니다.

SSD를 제외한 7개 지표의 그래프 축에는 단위와 시간이 표시됩니다. 메모리 축은 조회된 전체 용량, CPU·GPU 사용률은 0–100%입니다. 다른 축은 열린 창의 같은 시간 범위에서 축소되지 않아 작은 변화를 과장하지 않습니다. 최고·평균은 선택 구간의 유효한 샘플만 사용하며 미수집 구간을 이어 그리지 않습니다. 속도는 MB/s이고, 핵심값이 1,000 MB/s 이상이면 GB/s로 바뀝니다.

`—`는 미지원·미수집 또는 측정 준비 중입니다. 연결이 끊기면 마지막 값과 원래 측정 시각을 표시합니다. 메모리 클럭·시스템 전체 전력·IOPS 등 수집되지 않는 값은 만들어 표시하지 않습니다. 집계 인터페이스·장치, 센서 식별 정보, 클럭 지원 여부, 단위·계산법은 하단 **측정 기준 · 데이터 출처**를 펼쳐 확인합니다. 기술 설명은 기본적으로 접혀 있고, 실시간 수치·코어별 부하·센서 온도·용량 구성·클럭 제한 상태는 바로 보입니다. 중복된 아키텍처와 그래프 통계는 생략합니다. 닫기 버튼·ESC·배경 클릭으로 닫으며 갱신 중에도 시간 범위·스크롤·펼친 안내는 유지됩니다.



## 서비스 제어·모델 표시

모델 탭에서 시작·정지·재시작과 작업 결과를 확인합니다. 상세창에서 정지 상태일 때 실행 프로필을 선택할 수 있습니다. 서비스 추가에서 기존 사용자 서비스를 검색하고 연결 검사 후 제어 권한을 등록합니다. 로컬 CLI 등록도 유지됩니다. ComfyUI 진행/대기 작업 수, 프로세스 상태와 API 응답을 구분합니다. Hermes·연결 미설정 엔진은 프로세스 상태만 표시합니다. 모델 설치·삭제는 자동으로 하지 않습니다. [등록·교체 안내](MODELS.md).


ComfyUI·Hermes처럼 앱 주소가 등록된 카드는 **앱 열기**로 바로 접속합니다. 앱 자체 로그인은 유지됩니다. 모델 카드는 풀네임을 제목으로, 바로 아래에 양자화 방식을 표시하고 추론·서빙 엔진은 작은 글씨로 표시합니다. 양자화 미확인 시 확인 전으로 표시합니다. 이 값은 검증한 프로필 설정이며 정지 중 모델의 실행 상태를 뜻하지 않습니다.

서비스 제어 확인창 하단에는 같은 너비의 확인(라임색)·취소(빨간색) 버튼이 표시됩니다. 취소는 서비스를 변경하지 않고 창만 닫습니다.


모델 카드의 연필 버튼에서 서비스명·모델 풀네임·양자화·추론/서빙 엔진 표시를 수정합니다. 순서 변경에서 위·아래 버튼으로 배치한 뒤 저장합니다. 표시 정보와 순서는 Spark에 저장되어 다른 기기에도 적용되며, 실행 명령·포트·권한·모델 파일은 바뀌지 않습니다. 다른 기기에서 먼저 수정했다면 편집 창을 다시 열어 주세요. 휴대폰에서는 서비스 카드가 2열로 표시되고, 추가·교체 안내는 접어서 볼 수 있습니다. 상태 상세창의 현재/선택 구간 표시는 우측에 배치됩니다.

개인정보·데이터 흐름은 [개인정보 안내](PRIVACY.md)를 참고하세요. 앱 열기는 등록된 주소를 여는 기능이며 서비스의 Tailscale 접속 설정은 별도로 완료해야 합니다.


## 운영 기능

- 모델 카드 상단: 로딩은 황색, API 준비 완료는 라임, 실패는 빨강. 진행률을 제공하는 TensorFold 프로필은 실제 로딩 레이어 수를 표시합니다. 가중치 100%와 서버 준비 완료는 별개입니다. 진행률이 없는 엔진은 단계·경과 시간을 표시합니다. 프로세스만 확인되는 서비스는 별도 상태로 표시합니다.
- 실패 후 시작: 해당 서비스에 잔여 프로세스가 없는지 확인하고 systemd 실패/시작 제한을 초기화한 뒤 한 번 시작합니다. 다시 실패하면 원인과 조치를 경고창에 표시합니다. 메모리 부족을 우회하거나 다른 모델을 자동 종료하지 않습니다.
- 프로그램 탭: 현재 계정/전체 조회, 이름·PID 검색, CPU·RSS 메모리·실행 시간 정렬. 5초 캐시를 공유하며 탭을 볼 때만 수집합니다. CPU는 호스트 전체 기준이고 RSS는 공유 페이지를 포함하므로 합계를 실제 메모리 사용량으로 간주하지 마세요. 실행 인자·환경 변수는 읽지 않습니다.
- 설정 → 시스템 전원: 작업 중단 경고 → 비밀번호 재확인과 최종 실행의 두 단계입니다. 확인은 60초·동일 로그인·동일 작업에만 유효하며 한 번 사용하면 폐기됩니다. 비밀번호 오입력은 로그인을 해제하지 않습니다. 종료 후 다시 켜려면 로컬 전원 조작 또는 별도 원격 깨우기가 필요합니다.

패키지 설치 후 전원 제어는 Spark 로컬 관리자에게 한 번 활성화를 요청하세요. 아래 명령은 전원을 끄지 않으며 고정된 전원 명령만 허용합니다. 다른 사용자 세션이나 종료 방지 앱이 있으면 실행을 차단합니다.

```bash
sudo python3 /usr/lib/dgx-spark-control/packaging/configure-power.py --user "$(id -un)"
# 해제: 같은 명령 끝에 --disable 추가
```

엔진 진행률 연동은 로컬 실행 프로필에 `"startup_observer": "tensorfold"`를 지정하고 `services check/apply`로 검증·적용합니다. 현재 실행의 로그에서 정해진 카운터/오류 코드만 추출합니다. 설정된 API 준비 검사도 있다면 API 성공을 기다립니다. 원본 로그·프롬프트·인증 정보는 브라우저에 전송하지 않습니다.


### 날짜별 기록과 상단 전원 버튼
활동 기록은 기기 시간대의 날짜별로 최신순 정렬합니다. CLEAR / 기록 비우기는 확인창을 거쳐 현재 완료된 표시 기록을 모든 기기에서 비웁니다. 진행 중·새 기록, 서비스 복구 이력과 시스템 로그는 유지됩니다. 비우기 상태는 서버 재시작 후에도 유지됩니다. 우상단 전원 아이콘에서 재부팅 또는 전원 끄기를 선택하면 기존 경고 → 비밀번호 재확인 2단계로 이동합니다. 설정 하단 버튼도 계속 사용할 수 있습니다.


## 간결한 상태 표시
상단 버전/LIVE 배지를 제거했습니다. 버전은 설정과 하단에서 확인할 수 있습니다. 활동 기록의 행·날짜 간격을 줄여 PC와 휴대폰에서 더 많은 항목을 한 번에 표시합니다. 실패 설명과 기록 비우기 확인 절차는 유지합니다.


## 추론 그래프와 웹 등록
개요의 좌측 그래프는 선택한 LLM 서버의 출력·입력 처리량, 우측 카드는 모델과 실행 상태·진행/대기 요청·컨텍스트 한도·누적 출력 토큰을 표시합니다. TensorFold, vLLM, Strata 지표를 지원하며 빌드가 제공하지 않는 값은 —로 남습니다. 입력선은 경과 시간당 입력 토큰 증가량이며 프리필 연산 속도가 아닙니다. 출력은 전체 요청 합산이며 엔진 제공 구간 속도 또는 카운터 증가량을 사용합니다. 측정 기준에서 출처를 확인하세요.

이력은 개요를 보는 동안 5초 간격으로 수집하며 5분/30분/1시간을 선택합니다. 최대 4개 서버 × 720개 샘플을 메모리에 보관하며 재시작하면 지워집니다. 연결 실패·수집 공백은 보간하지 않습니다. 현재 엔진이 쉬고 있으면 0이 정상입니다.

모델 → 서비스 추가: 기존 사용자 systemd 서비스 선택 → 연결 유형·API 포트·앱 주소 입력 → 제어 활성화 선택 → 연결 검사 → 연결 저장. 저장은 서비스를 시작하지 않습니다. 정지된 서비스는 API 미확인 상태로 등록하고 이후 시작할 수 있습니다. 포트는 이 Spark의 로컬 포트이며 루프백 연결이 거절되면 OS가 확인한 자신의 IPv4 수신 주소만 사용합니다. 외부 서버 주소·셸 명령은 입력받지 않습니다. 기존 카드의 연결 설정에서 관측 API와 제어 설정을 수정할 수 있습니다.

다른 기존 서비스를 기존 카드의 새 프로필로 추가할 수 있습니다. 실제 프로필 전환은 정지 → 프로필 선택 → 시작입니다. 모델 파일 버튼에서 폴더를 저장·검색하고 후보를 모델 목록에 등록할 수 있습니다. 목록 등록은 파일의 위치·표시 이름을 보관하며 실행 명령을 생성하지 않습니다. 엔진/가중치 다운로드·삭제, Docker 단독/시스템 서비스 제어, 파일을 바로 실행하는 엔진 템플릿 생성은 이번 범위에 포함되지 않습니다.

## 메모리 카드 사용률
메모리 카드 오른쪽에는 사용량 ÷ OS 가용 총량 × 100을 소수점 한 자리로 표시합니다. 왼쪽 GiB·하단 총량·게이지와 같은 기준이며 설치 용량과 다를 수 있습니다. 미수집·연결 끊김은 —%로 표시합니다.


## 서비스 편집 통합
카드의 별도 CONNECTION 버튼을 제거했습니다. 우측 연필(EDIT) → 표시 정보 / 연결 설정에서 모델·엔진 이름과 API 포트·앱 주소·제어 권한을 관리합니다. 탭을 바꾸어도 입력 초안은 유지하며, 저장은 현재 탭에만 적용됩니다. 연결은 검사 → 확인 → 저장 절차를 유지합니다. 취소·닫기는 저장하지 않습니다.

## 추론 패널 정렬
PC의 추론 그래프·가동 LLM 패널은 같은 너비로 상단 지표 열에 맞춰 표시됩니다. 그래프와 여백을 줄이고 제목·하단 버튼을 정렬했습니다. 좁은 화면에서는 두 패널을 세로로 표시하며 상단 8개 지표는 기존 최소 2열을 유지합니다.

## 편집·필터·복구
Spark 이름 입력은 저장·입력 취소 전까지 자동 갱신으로 덮어쓰지 않습니다. 서비스 편집의 탭별 변경은 각각 저장하며, 다른 탭의 변경이 남으면 그 탭을 계속 표시합니다. 저장 실패 시 초안이 유지되고, 닫기 전에 변경을 버릴지 확인합니다. 브라우저 새로고침은 미저장 경고가 표시될 수 있습니다. 초안을 영구 저장하지는 않습니다.
정지 앱은 ‘실행 후 열기’, API 미준비는 ‘접속 준비 중’, 프로세스만 확인되는 앱은 ‘열기 · 미확인’으로 구분합니다. 이는 실제 앱 로그인 성공을 보증하지 않습니다.
모델 파일은 목록 조회이며 실행 설정 생성이 아닙니다. ‘기존 실행 서비스 연결’에서 이미 구성된 사용자 서비스를 연결하세요. Docker/터미널 실행 환경 설치는 Spark에서 별도로 수행합니다.
기록은 검색·실패/중단 필터·날짜 접기를 지원합니다. 기록 비우기는 필터 밖의 완료 기록도 포함하며 모든 기기에 적용됩니다. 프로그램의 서비스 프로세스 필터는 일반 시스템/데스크톱 그룹을 제외한 서비스 그룹을 표시하며 등록 모델만의 목록은 아닙니다.
패키지 설치판 업데이트는 새 .deb를 apt로 설치하며 압축판 스크립트와 혼용하지 않습니다.
