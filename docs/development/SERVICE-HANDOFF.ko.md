# LLM을 통한 서비스·모델 추가 가이드 — 0.3.4

설치·등록·수정별 복사 요청문은 [LLM 작업 안내서](../LLM-GUIDE.ko.md), 실제 구현 계약과 명령은 [MODELS.md](../MODELS.md)를 따른다. 웹의 기존 사용자 서비스 검색·연결 검사·선택적 제어 등록·표시 편집과 정지 후 프로필 선택을 지원한다. 고급 로컬 등록은 아래 절차를 따른다.

기존 systemd 서비스의 추가·교체는 대시보드 소스를 고치지 않고 로컬 등록 정보로 처리한다.

1. AGENTS.md, ../MODELS.md, MODEL-SERVICES-PLAN.md를 읽는다. 현재 실행 중 서비스, 기존 등록, 버전, 메모리/포트 충돌을 조회한다. 원시 키/환경변수/전체 명령줄은 보고서에 출력하지 않는다.
2. 설치와 등록을 구분한다. 이미 설치된 서비스는 재설치하지 않는다. 새 엔진/가중치 설치는 사용자가 지정한 범위와 모델 리비전을 먼저 확정한다.
3. 지원하는 manager와 adapter를 선택한다. 지원하지 않는 엔진도 systemd-user로 시작/정지를 연결할 수 있지만 readiness/metrics는 미지원으로 둔다. API 이름이 비슷하다는 이유로 다른 엔진 어댑터를 사용하지 않는다.
4. 기존 user unit을 유지하거나 별도 unit을 만든다. 실행 인자·환경 파일은 Spark의 로컬 파일에 유지한다. 대시보드 cgroup의 자식으로 모델을 실행하지 않는다.
5. 새 service/profile/asset ID를 정하고 기존 설정에 병합한다. 경로·endpoint·키는 개인 설정에만 기록한다. 동일 포트와 자원 그룹, 실제 연결 관계를 지정한다.
6. services export로 비공개 파일에 내보내고 services check로 검증한다. 이전 revision을 백업한 뒤 services apply --file FILE --expected-revision N으로 원자적으로 저장한다. 문서의 예제 JSON을 현재 앱 config에 그대로 넣지 않는다.
7. 시작/교체가 요청된 경우에만 적용한다. 실행 중인 다른 작업은 임의 종료하지 않는다. 준비 확인과 실제 소규모 추론 검증은 구분하여 기록한다. 추론 검증은 요청된 작업 범위에 포함될 때 수행한다.
8. 중지/복구 경로를 확보하고 상태·포트·모델 ID를 대조한다. 모델 파일 삭제는 등록 해제와 별도이며 명시적으로 요청되었을 때만 진행한다.
9. 설치한 엔진 버전·프로필·검증 결과·남은 제약을 로컬 기록에 남긴다. 새 코드가 필요하면 기존 어댑터를 변경하기보다 명확한 capability로 확장한다. 깃허브 공개는 별도 지시에 따른다.

## 사용자 요청 예시

“이 Spark에 설치한 새 추론 서버를 대시보드에 등록해줘. 기존 서비스와 모델 파일을 보존하고, 서비스 등록과 실행 프로필만 추가해. 이 저장소의 AGENTS.md와 모델 서비스 설계서를 읽고, dry-run으로 변경점을 검증한 뒤 적용해. 실제 시작·교체는 내가 요청한 서비스에만 해줘. 개인 설정과 키는 공개 저장소에 넣지 마.”

ComfyUI 업데이트는 기존 unit/포트/API 계약을 재확인한다. 체크포인트 추가만으로 서버 unit을 새로 만들 필요는 없다. Hermes의 공급자 교체와 로컬 추론 서버 교체는 서로 다른 설정이므로 연결 관계를 명시적으로 확인한다.
